# Local hardware market monitor contract

Local FastAPI + SQLite app, static UI at `/`. No external AI required. Source is `demo` or `live`; never mix them. All API times ISO 8601 with timezone; dates shown Asia/Shanghai. Categories: `phone`, `gpu`, `ram`, `cpu`, `motherboard`, `storage`, `computer`, `component`. States: `on_sale`, `sold`, `delisted`, `unknown`.

## UI endpoints

- `GET /api/health`: `{ok:true}`.
- `GET /api/overview?source=demo&days=30&category=all&model=all`: `{source,days,summary,trend,distribution,models,coverage}`. `summary`: `{total_items,active_items,new_items,confirmed_sold,sold_ratio,median_price,p25_price,p75_price,excluded_items,last_observed_at,published_items}`. `sold_ratio` is percent 0..100 of first-seen cohort in window, confirmed_sold/new_items (null if empty). `total_items` and active_items use latest state of normal-quality items observed within the selected window (same last_seen filter as items). `confirmed_sold` is cohort sold count (not all-time). Median and quartiles only normal-quality on-sale items. `published_items` counts valid known publication times in the selected window. `trend`: `[{date,median_price,new_items,confirmed_sold,samples}]`, daily observed on-sale last snapshot/item median (not transaction price), new first-seen items, sold first confirmation. `distribution`: `[{label,count,min,max}]`. `models`: `[{model,category,active_items,median_price,new_items,confirmed_sold,sold_ratio}]`. `coverage`: `{message,price_basis,ratio_basis}`.
- `GET /api/items?source=demo&days=30&category=all&model=all&status=all&q=&page=1&page_size=20&include_excluded=false`: `{items,total,page,page_size}`. Each item: `{id,item_id,title,url,category,model,price,status,quality_flags:[str],excluded:bool,first_seen,last_seen,published_at,source,evidence,sold_price}`. `id` is internal int.
- `GET /api/items/{id}/history`: `{item,observations:[{observed_at,price,status,evidence,sold_price}]}`.
- `PATCH /api/items/{id}/status`: `{status,evidence,sold_price?}` manual human-confirmed evidence required for sold and delisted, appends observation.
- `GET /api/tasks`: `{tasks:[{id,name,keyword,category,model,min_price,max_price,exclude_keywords,interval_minutes,enabled,last_run_at,next_run_at,last_error,source}]}`. `exclude_keywords` list. interval >=30 min. Defaults disabled.
- `POST /api/tasks` / `PATCH /api/tasks/{id}`: create/edit fields above, `source=live` only; return task object. model default `auto`.
- `DELETE /api/tasks/{id}`: `{ok:true}`.
- `POST /api/tasks/{id}/run`: queues collector, `{ok:true,message}`. Collects live only, collector unavailable gives actionable 409.
- `GET /api/runs?limit=20`: `{runs:[{id,task_id,task_name,status,started_at,finished_at,items_seen,items_saved,error}]}`.
- `GET /api/collector/status`: `{available,session_exists,browser_installed,login_running,message}`. Session existence does not prove session is valid.
- `POST /api/collector/login`: `{ok:true,message}` opens local visible Chromium for user login. Login state saved locally by collector. No remote captcha solving.
- `POST /api/import`: `{source:"live",task_id?:int,records:[...]}`. Normalized record `{item_id,title,price,status?,evidence?,observed_at?,published_at?,url?,category?,model?,sold_price?}`. Also accept upstream monitor rows via normalization. Transactional validation; report `{imported,skipped,warnings}`. live only. `status=sold` requires explicit evidence. CSV UI parses into records before sending. Max 5000 records.
- `GET /api/export?source=demo&days=30&category=all&model=all&include_excluded=false`: UTF-8 BOM CSV of matching latest items with evidence, explicit source, status, no secrets. Spreadsheet formula cells escaped.
- `POST /api/demo/reset`: deterministic, idempotent-ish reseed demo rows only; never touches live.

## Root-owned collector interface

`app.collector` exposes `collector_status() -> dict`, `start_login() -> dict`, `async collect(task:dict) -> list[dict]`. `CollectorError` has a user-actionable safe message. `collect` returns records accepted by normalization (including keyword passed as context); raises on login/gate/parser failures, never quietly returns zero on parser breakage. User login persisted under ignored `data/browser_profile/`; global run lock managed in service. Backend imports lazily. Backend creates app via `create_app(db_path=None)` for test isolation, exposes `app = create_app()`; database overridable by `XIANYU_DB_PATH`. `app/service.py` owns storage/analytics, `app/main.py` API and scheduler. Backend can alter internal structure while retaining this API. Root owns pyproject, collector, README; frontend owns app/static; backend owns all other app/*.py and tests.
