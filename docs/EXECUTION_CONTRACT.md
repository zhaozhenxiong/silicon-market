# Execution API contract — implementation 2026-10-30

Owners: backend agent catalog/jobs/main/service/official storage; indices agent `app/indices.py` + its tests; frontend static; root `app/mobile_reader.py`, `automation/`, mobile interaction and integration. Do not modify another owner's files without coordination.

## Catalog and mobile backfill

- `GET /api/catalog`: `{items:[{id,category,model,query,scope,enabled,status,target_days,verified_days,missing_days,coverage_pct,last_error}], total}`. Source initial catalog: normal live item distinct category/model plus explicit monitor-task targets, never demo. Deduplicate canonical scope/query. `scope` is object; preserve unknown storage/condition/filter instead of claiming verified variants. `status`: pending/ready/no_market/needs_review/waiting_device/complete/partial.
- `POST /api/catalog/sync`: idempotently discover eligible live models and tasks, `{added,total}`. Existing operator settings preserved. Exclude unknown model labels. Existing official snapshots may attach as historical legacy proof but only verified dates/scope count; show legacy count separately until match verified.
- `PATCH /api/catalog/{id}`: editable `{query,scope,enabled,status,last_error?}`. Category/model identities versioned/validated; avoid silently widening specifications.
- `POST /api/mobile/batches`: `{catalog_ids?:[int],days:180,end_date?:"YYYY-MM-DD"}` creates persistent unique date jobs, defaults enabled targets and yesterday Shanghai. `{id,status,total_targets,total_days,existing_verified}`.
- `GET /api/mobile/batches`: `{batches:[{id,status,days,end_date,total_targets,total_days,verified_days,pending_days,review_days,unavailable_days,coverage_pct,created_at}]}`.
- `GET /api/mobile/jobs?batch_id=&catalog_id=&limit=100`: `{jobs:[{id,batch_id,catalog_id,category,model,query,target_date,status,attempts,price,error,evidence_url}],total}`; paginate with offset optional.
- `POST /api/mobile/claim`: `{worker_id,catalog_id?,limit?:40}` returns `{lease_token,jobs:[...],catalog:{...},lease_expires_at}`. One device lease, atomic claim pending or expired jobs, block concurrent worker ownership. Heartbeat extends bounded lease. Explicit requires connected worker; no phantom active device. Different scopes serial; jobs grouped one catalog.
- `POST /api/mobile/heartbeat`: `{worker_id,lease_token,device_status,message?}`; status ready/locked/verification/disconnected/reading/waiting_user. `{ok:true}`. Waiting/device states release or extend safely.
- `POST /api/mobile/readings`: `{worker_id,lease_token,readings:[{job_id,displayed_date,price,evidence_filename,observed_model,observed_query?,scope?,read_method:"mobile_screen_ocr",ocr_text?,parser_version?,verification_count:2}], ...}`. Evidence safe local filename in `data/market_evidence/`; verify actual image signature, exact displayed date matches target, nonnegative finite price, matching model/scope (alias tolerant only explicit mapping), identity/lease. Transactional accept, revisions/conflicts retained. Raw `ocr_text` no secrets; stored screen readout is not inferred from coordinate. No future days. Successful jobs are source `mobile_screen_ocr`, separate from manual 15 points. Reuse verified same scope/date across batches, preserve evidence hashes. Import successful reads into official snapshots for existing UI (snapshot creation grouped allowed) or expose via `/api/official-market` without deleting manual records.
- `POST /api/mobile/jobs/status`: `{worker_id,lease_token,job_ids:[...],status:"needs_review"|"unavailable"|"waiting_device"|"pending",message}`; unavailable not successful coverage. No platform challenge solving.
- `POST /api/mobile/batches/{id}/retry`: resets review/failed/waiting jobs for bounded retry; never erases verified points.
- `GET /api/mobile/status`: `{device_status,worker_id,last_heartbeat,message,active_batch,active_catalog,connected}` from real heartbeat freshness (expired -> disconnected).
- `GET /api/mobile/evidence/{reading_id}` safe image evidence serving if useful.

Batch complete only when every target day is verified. Processed with gaps => partial. Device lock not repeated destructive retry. Yesterday cutoff, 180 calendar dates. Bootstrap target catalog/batch once during integration, root invokes actual mobile executor. Persistent listing queue can be a separate jobs kind but must retain existing schedule/operator task settings and retry logs.

## Real index API

- `GET /api/indices?days=180&category=all`: `{version,methodology,weights,price_indices:[{id,basis:"official"|"listing",name,status,basket:[{category,model,weight}],base_start,base_end,points:[{date,value,coverage_pct,missing_models:[]}],message}],features:[{category,model,status,score,factors:[{key,label,weight,raw_value,score,contribution,status,reason}],missing_reasons:[]}],coverage:{...}}`.
- `POST /api/indices/rebuild`: `{category?:"all",days?:180}` persists a versioned snapshot based solely on live/official verified data; returns build id + status. Prefer the same deterministic method used by GET; save inputs version/hash and fixed basket/weights/parameters. Never synthesize missing factors/history. Geometric price index requires common consecutive 7-day baseline and immutable basket, null missing-day output. No common baseline -> insufficient_data (not fake value100). Composite fixed weights 30/25/20/15/10; per plan 30 valid factor-day calibration and mature cohort, missing required factor -> no overall score. Expose raw values even when not calibrated. official metric rolling_7d_sold_mean distinct from listing. No in-process `Store.initialize()` side effects from indices.
