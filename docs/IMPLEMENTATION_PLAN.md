# 硅价：手机半年历史初始化、持续挂牌采集与真实综合指数计划

版本：计划 v1.0 · 2026-10-30 · 尚未执行本轮开发或全量采集。

## 1. 目标与范围

按两个阶段建设数据，再将首页“演示数据”入口替换为“综合指数”：

1. **首次初始化**：所有目标型号的近半年历史，统一从手机闲鱼 App 行情页自动逐日读取。
2. **后续积累**：挂牌商品及价格从实际采集时间开始持续记录；App 行情可另外补最近日期、修补历史缺口。
3. **综合指数**：只使用真实采集数据，展示类别、型号和固定观察篮子的加权价格及市场特征。

“所有型号”以版本化的目标型号目录为准，覆盖手机、显卡、内存、CPU、主板、存储、整机和元件。先导入现有监控任务和已识别型号，再补目录；这不是已经穷尽闲鱼平台全部型号。新增型号进入同样的手机历史初始化流程。

App 不提供某型号、不能筛选到所需规格，或未覆盖某日期时，要留下明确状态，不能用另一规格或生成数据替代。

## 2. 保留的数据口径

| 数据 | 来源与粒度 | 用途 | 限制 |
| --- | --- | --- | --- |
| 历史价格参考 | 手机 App 显示的“某日近7日成交均价”，一型号/筛选范围/日期一条 | 半年价格参考、动量、平滑价格波动特征 | 按日读取的7日滚动均价，并非该日独立成交均价 |
| 挂牌历史 | 实际采集到的商品ID、时间、挂牌价格、状态 | 挂牌中位价、供给观测、报价离散、样本售出跟踪 | 不能由 App 成交曲线或商品发布时间倒推过去挂牌价 |
| 指数 | 原始记录经过固定版本的规则计算 | 比较类别和型号变化 | 显示篮子、权重、基期、有效范围和输入版本 |

App 行情如果汇总所有容量/成色，须保存其实际范围。只有页面确实选择了256GB等筛选条件，才能标为该规格的行情；不能把同一宽口径曲线复制给多个细分SKU再重复计权。

现有14900KF的15个核实日期及逐点截图继续保留，状态为“部分覆盖”；待同一口径复核后并入全量读数，不插值扩展为180条。

## 3. 第一阶段：手机自动建立半年基线

### 3.1 建立型号与行情范围目录

每项记录分类、规范型号、容量/版本、搜索别名、App页面标题及筛选条件。为平台行情范围单独设置 `market_scope_id`，避免多个SKU指向同一汇总曲线后重复统计。

初始化批次固定 `catalog_version` 和截止日。默认目标为启动日前一天结束的180个自然日，时区统一 Asia/Shanghai；当天未结束的数据另存，不混进完整日基线。

目录中的型号都要尝试手机采集，并区分：可逐日读取、仅宽口径行情、尚未找到行情、日期不提供、需要人工处理。采集范围和指数可入选范围分别维护。

### 3.2 先打通可长期运行的手机采集器

沿用当前 Mac + iPhone 镜像，封装 `MobileDriver`：截图、页面识别、搜索型号、设置筛选、触碰曲线、读取日期/金额和检查锁屏。

本次助手已经可以操作镜像，但 FastAPI 后端不能直接继承聊天工具的能力。先验证独立采集进程可通过受支持的本机控制通道运行，并明确其安装、权限和生命周期；这一项通过前，不宣称产品已具备无人值守手机采集。

用户本人处理 Touch ID、登录和平台验证。锁屏、连接中断或验证页面出现时，任务转为等待状态；已取得数据和进度保留。

### 3.3 逐日读取与精细定位

每个型号执行：

1. 搜索并打开行情，确认页面型号及筛选条件与目录一致。
2. 识别曲线有效区域与日期范围，建立粗定位。
3. 对每个目标日期移动到附近位置，以浮层**实际显示的日期**校正位置，直到准确读到目标日期。
4. 同时读取日期、金额、单位、指标名称；保存截图、截图哈希、采集时间和解析版本。
5. 日期吻合且金额复读一致后入库；冲突、识别失败或异常跳变进入复核队列。

坐标仅用来寻找日期，不能用来生成日期或估算价格。OCR先在本机执行，金额单位与型号由独立规则校验；关键读数复读比对。

同一像素可能对应多个日期。遇到跳日时尝试更细步长或页面正常提供的缩放/拖动交互；若仍无法分别读到，保持缺失并标注“界面无法分辨”，不能靠插值完成任务。

### 3.4 任务队列与恢复

新增持久化任务：`批次 → 型号/行情范围 → 目标日期`。手机交互串行执行，解析与入库可独立排队。

任务状态包括待采集、运行、等待解锁、等待平台验证、待复核、成功、无源数据、界面不可读取和重试耗尽。使用租约、心跳、幂等键及有界重试；断电重启后从缺失日期继续。

日期读数唯一键至少包含 `market_scope_id + metric + date`。同日冲突保留原始读数和修订原因，不静默覆盖证据。

### 3.5 完成标准

- 每型号展示目标日期数、有效日期数、缺失日期、待复核数、不可获取原因及最后成功时间。
- `完整覆盖率 = 已核实目标日期数 / 180`，不能用“已处理任务数”冒充覆盖率。
- 只有180个目标日期全部有效，才标“180日完整”。无源数据或上市前日期也须列明，另显示可用日期覆盖情况；不能据此把总覆盖标为100%。
- 全批次只有全部目标型号达到对应验收状态才结束；部分型号无法完整获取时，标“批次已处理，存在缺口”，列出缺口，而非“全部半年数据已完成”。
- 验证重复运行、程序中断恢复、日期跨年、单位变化、页面布局变化和多规格误匹配。

## 4. 第二阶段：持续积累真实挂牌

保留现有网页挂牌采集器、商品ID去重和观察历史，接入持久化队列。挂牌任务与手机历史任务分别调度，避免手机回填阻塞当前挂牌采集。

每次保存实际观测时间、挂牌价、可得的发布时间、状态和证据。商品首次进入搜索结果只能称“新增观测”；搜索结果中消失不计为成交。

同一商品每日按最后一次有效观测进入当日价格统计；原始快照全部保留。持续复查既有在售商品，记录首次明确售出事件。

每个任务记录搜索页数/采样上限、筛选条件、成功率和跟踪覆盖。修改搜索范围或采集频率形成采样配置版本，避免采样变多被误认为市场供给增加。

挂牌首次扫描是一批存量发现，应标为初始化批次；供给变化因子在固定采样配置完成预热后启用。

## 5. 将“演示数据”改为真实综合指数

### 5.1 产品结构

首页入口调整为“真实行情 / 综合指数”。生产界面不再展示模拟商品、模拟价格和演示重置入口；合成数据迁移到开发测试夹具。

已有真实商品、App截图及历史读数保留。数据库先备份，迁移脚本只处理已确认的演示来源，提供迁移报告；本计划本身不删除任何数据。

综合指数页同时展示：

- **价格参考指数，基期100**：App历史成交参考与挂牌价格分别成线，使用固定篮子，便于比较涨跌。
- **综合市场特征评分，0–100**：真实价格、样本流动性、供给观测、报价集中度和稳定性的加权结果。
- 每项因子的原值、标准化值、权重、贡献、数据时间与覆盖情况。

评分表示相对各型号自身固定校准期的市场特征状态；高低由公开的因子方向定义。它适合看状态变化，不是跨型号的绝对流动性排名，也不能直接解释为便宜、值得买或未来收益。原始因子值始终同屏保留。

### 5.2 加权价格指数

先按型号归一到同一基期，再汇总，避免高价显卡直接支配所有类别的人民币均价。

```text
型号价格相对值 r(i,t) = P(i,t) / P(i,base)
观察篮子价格指数 I(t) = 100 × exp(Σ w(i) × ln(r(i,t)))
Σ w(i) = 1
```

`P`按指数来源固定：App指数使用该日对应的近7日成交均价；挂牌指数使用每日去重正常样本的挂牌中位价。二者分别确定基期，不拼接成一条历史线。

首版基准价取固定篮子共同完整覆盖的首个连续7日窗口内，各型号参考价格的中位数。基准窗口与价格都要保存；找不到这样的共同窗口时，该篮子尚未达到发布条件。挂牌指数的基准窗口只能来自实际采集后的日期。

首版建议采用“纳入类别等权、类别内型号等权”，对同一App行情范围只计一次。它是公开的初始观察篮子规则，不叫成交量加权；后续只有取得同口径、可核验成交量，才另设计量权版本。

篮子成员、权重和基期按版本冻结。每个指数先选择满足数据条件的固定型号篮子；其覆盖范围明确列出，未覆盖类别不被算作全市场覆盖。某日成分缺失时先补采，仍缺失则该日正式指数留空，不临时换成分或重新分配权重。更新篮子产生新版本，保留旧结果。

### 5.3 综合特征评分初始方案

以下为**待试运行校准的v0建议权重**，并非已经用数据证明的最优权重。

| 因子 | 建议权重 | 原始定义与方向 | 数据来源 |
| --- | ---: | --- | --- |
| 价格趋势 | 30% | 同口径参考价格28日变化；上涨方向得分更高 | App近7日成交均价序列 |
| 跟踪流动性 | 25% | 成熟首见队列在14日内被明确观察为售出的比例；更高方向得分更高 | 后续商品状态与证据 |
| 供给压力 | 20% | 固定采样配置下7日新增观测相对可比前7日的变化；供给压力降低方向得分更高 | 后续挂牌采集 |
| 报价集中度 | 15% | 同型号同日 `(P75-P25)/中位价`；离散更低方向得分更高 | 后续挂牌价格 |
| 参考价格稳定性 | 10% | 最近28日平滑参考价格每日对数变动的标准差；更稳定方向得分更高 | App近7日成交均价序列 |

价格趋势、流动性、供给等含义不同，评分必须允许展开拆解；供给收缩等现象不单独解释为需求增强。稳定性描述的是已经平滑的参考价格，不能当成逐笔成交风险。

流动性使用固定首见批次、同等14日观察期，分母为首次观测时正常在售的唯一商品，分子为14日内首次确认售出的唯一商品。初见已售、下架、未知和搜索消失不作明确售出；未确认状态仍保留在原分母，并公布跟踪覆盖。

### 5.4 标准化、缺失与生效条件

- 不把人民币、比例、数量直接相加。因子先转成0–100：使用在计算日前冻结的校准窗口分位点做有界标准化，并配置正反方向；常量因子和极端值有单独规则。
- 首版标准化建议为 `100 × clip((x-Q05)/(Q95-Q05), 0, 1)`，反向因子取 `100-得分`；`Q05/Q95`来自预先冻结的、至少30个有效因子日的校准样本。已实际观测且恒定的因子在分位点重合时记中性50；未知或未采到的因子保持缺失。截断后的原始异常值及标记仍可查看。
- 校准窗口、最小样本量、因子方向、异常规则及参数纳入 `index_version`；后续调整不改写旧版本。
- 测试等权、上述建议权重及合理扰动权重的结果，检查高度相关的因子是否重复计权。权重敏感性明显时，在指数说明中保留该限制。
- 因子缺失不填0、不填50，也不每天悄悄重分配权重。正式综合评分要求该版本全部必需因子达标；未达标时显示已具备因子和“等待数据成熟”。
- 挂牌价格/离散因子的试运行最小样本量建议20件/型号/日，阈值可配置并由试运行修订；达不到不影响原始记录查看，但不能自动计入正式评分。
- 跟踪流动性须有成熟14日队列、足够队列样本和跟踪覆盖；供给须完成预热且采样配置可比。校准历史也需达到版本要求，具体启用日由数据决定，不写死上线后第几天。
- App半年历史可先发布价格参考指数及价格特征。过去没有实际挂牌/状态记录的日期，不能回填供给、售出占比或完整综合评分。

型号综合评分为五项标准分按表中权重求和；类别及全篮子综合评分再按该版本冻结的型号权重求和。因子权重和型号权重分别管理，均须归一为1，并遵循上述必需因子与固定成分完整性要求。

## 6. 工程落地清单

| 模块 | 主要工作 | 对现有实现的关系 |
| --- | --- | --- |
| `catalog` | 型号目录、规格、别名、App行情范围、目录版本 | 接现有型号识别和监控任务 |
| `mobile_driver` / `mobile_reader` | 独立手机控制适配、页面识别、日期定位、OCR与复读 | 当前镜像操作能力的产品化，先做可行性验证 |
| `jobs` | 型号×日期任务、租约、心跳、暂停续跑、设备串行锁 | 补充现有内存中的运行状态 |
| `official_market` | 逐点证据、采集批次、冲突修订、覆盖矩阵 | 扩展已有App快照与15点记录 |
| `collector` / `observations` | 持续挂牌、样本跟踪、采样配置版本 | 保留已运行采集链路 |
| `indices` | 基期、固定篮子、标准化、因子、权重、版本和重算 | 新增派生层，不修改原始记录 |
| 总览/采集中心 | 手机回填进度、真实行情、综合指数、因子贡献和覆盖说明 | 替换生产演示入口，保留现有真实样本浏览 |

原始观测、读数修订、特征与指数分层保存；同一输入版本与指数版本重算结果应一致。

## 7. 实施顺序与里程碑

| 阶段 | 交付物 | 进入下一阶段的验收 |
| --- | --- | --- |
| P0：目录与手机采集验证 | 冻结首批目录；独立手机驱动；日期可达性报告 | 选3–5个代表型号测试完整目标日期；逐日定位、设备状态与证据可用，不再依赖人工逐点点击 |
| P1：全量手机初始化 | 所有目标型号的180日任务、覆盖矩阵和断点恢复 | 每一目标日期有明确结果；有效点可追溯，缺口未伪装为完成；中断恢复不重复记账 |
| P2：持续真实挂牌 | 固定采样配置、正常调度、商品状态跟踪与覆盖 | 日统计去重正确，存量初始化不制造供给信号，失败不形成零商品行情 |
| P3：真实价格指数与生产页面迁移 | App/挂牌两条价格指数；真实行情/综合指数入口 | 固定篮子与基期可复算；模拟数据不进入生产指数；原真实记录完整保留 |
| P4：综合特征评分 | 达标因子、权重版本、贡献拆解及敏感性检查 | 必需数据成熟，同口径可比较；缺失规则、旧版本重算和修订链路均通过 |

P2可在P1批量运行期间并行积累挂牌，手机仍专用于首次历史回填。P4等待数据成熟，不用模拟值赶进度。

暂不承诺“几个小时采完所有型号”。在P0测得每个成功日期的实际耗时、型号切换耗时、重试率与每日可用设备时间后，再估算批次时间：

```text
预计工作量 = 目标型号数 × 目标日期数
预计采集时间 = 各成功读数耗时之和 + 页面切换 + 复核重试 + 人工解锁等待
```

## 8. 本轮计划的完成定义

用户最终能看到：哪些型号已有180个真实日读数、哪些缺日及原因；真实挂牌从哪天开始；每条指数用了什么范围、基期和权重；某天为何没有综合评分。

真正完成全量初始化需要实际手机运行验收。本文件是待实施计划，不表示已取得所有型号半年逐日数据，也不表示手机长期自动采集已实现。
